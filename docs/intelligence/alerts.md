Conditions worth a person's attention, raised automatically and cleared

## Purpose

Every section can produce a number that is quietly wrong or quietly bad — a SKU
losing money, a fee that drifted, stock about to run out. Nobody watches every
number.

An alert is the assertion that one of them crossed a line the business cares
about, carrying enough context to act without first going to find it.

## Business rules

1. **An alert names a severity, a category and a subject.** Severity says how
   urgently; category says which team; the subject — usually an ASIN or a metric
   — says what to open.
2. **An alert carries the figure that triggered it**, so the reader can judge it
   without leaving the page.
3. **Alerts are resolved by a person, never expired automatically.** A condition
   that stops being true does not mean anybody saw it. See `INT-D-002`.
4. **The categories are fixed** — inventory, PPC, performance, system — so an
   alert always has an owner.

## States

| State | Meaning |
|---|---|
| Open | raised, not yet acted on |
| Resolved | a person has dealt with it |

## Edge cases

- **The same condition on consecutive runs.** Raised once and kept open rather
  than duplicated, so the list is a list of problems rather than of checks.
- **A condition that resolves itself.** The alert stays open until someone closes
  it — deliberately, by rule 3.
